# PC witness and upgrade transport — 0.67

Step 4/6. This lot supplies an authenticated transport, a durable Windows implementation of the 0.66 witness protocol, and a non-pairing Windows update kit. These are code capabilities, **not an activated production continuity proof**. The production launcher still runs 0.65 with no witness owner or account-erasure operations.

## Transport while the application is stopped

`createWitnessTransport` pins the original destination identifier, pairing timestamp and registry identity. Each exchange has a fresh random request identifier in addition to the core's fresh challenge. Only the existing native backup bearer capability, freshly resolved before delivery and before acceptance, may poll or answer. Cookie/Origin/Sec-Fetch requests are refused; authority is exclusively the primary origin. Revocation, pause or a replacement pairing blocks confirmation. No archived receipt, URL credential, browser session or uncorrelated/late response authorizes continuity. Poll/body/concurrency/size/lifetime limits are fixed. Core authentication of all encrypted journals remains mandatory: a transport response alone does not authorize erasure.

The optional `witnessControl` dependency in the recurring supervisor owns the public port in the parent; ordinary traffic is streamed once to the fixed loopback child port (public port + 1). It starts before stopped-child closure checks and survives child drainage/capture. It is not exposed through a public query, environment toggle or current launcher flag. The child accepts the fixed internal `--parent-gateway managed` IPC option and binds only loopback. The gateway removes incoming peer stamps and supplies the actual socket peer. A WeakMap-backed helper preserves the original peer for authentication/admission limits. Other forwarding headers grant no peer identity. Existing deployments keep the old direct listener by default.

## Windows durability and update

The PowerShell 5.1 witness uses an owned protected local NTFS directory, outside the user-selected archive folder. It stores canonical complete snapshots containing only opaque encrypted journal files, immutable consecutive publication names, and a head published after the snapshot. File handles reject reparse points, nonregular files and multiple hard links. Writes use write-through handles and `Flush(true)`; head replacement uses `MoveFileExW` with replace/write-through flags, followed by a durable reread. No CRM or GPG key is transferred to this component. Hardware/power-loss behavior still depends on Windows and the physical storage honoring flushes; this is not protection against the owner rolling back the whole PC.

Missing heads, gaps/forks, partial publications, equal-revision substitutions, lost journals, revision jumps and binding changes refuse confirmation. Exactly one complete unpublished successor can finish the head; older history cannot be silently discarded. Bounds match the Node reference: 9,990 journal files, 64 MiB snapshot, 10,000 publications and 1 GiB history. Initialization is a separate explicit empty-directory function, **never called by the worker**. Losing the witness does not recreate a new empty proof.

The paired-PC UI adds **Mettre à jour le PC** / **Update this PC**. Its authenticated CSRF-protected download requires a fresh matching session after ZIP preparation. Unlike reconnecting a machine, this ZIP contains no pairing code or bearer token. `Mettre-a-jour.cmd` reads the existing per-user DPAPI configuration, locks the agent, validates and stages script replacement, then updates the limited interactive scheduled tasks. Folder, location identifier, credential and receipt are preserved. Archive checks remain every 15 minutes. A separate one-minute witness task keeps large archive downloads from occupying the witness worker. Until a separately controlled genesis has created its head, this task performs no network request and cannot certify anything. The ordinary folder shortcut remains usable.
